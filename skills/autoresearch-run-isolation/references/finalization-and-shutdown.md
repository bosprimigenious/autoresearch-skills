# 最终化与关机

付费实例的“停止研究”“拉回证据”“关闭操作系统”“云平台停止计费”是四个不同状态，不能互相代替。推荐按下面两阶段终止。

## 阶段一：冻结运行并完成最终复验

1. 停止调度器继续创建新轮，但允许当前合法方法—评测循环闭合；记录最后一个计入时长的 receipt。
2. 从原始 activity、receipt 和评测摘要重算有效区间并集。只计闭合、非 blocked、实际包含方法变化或评测的区间；排队、安装、网络故障、重试等待和未闭合尾轮为零信用。
3. 对两条轨迹各自选中的最终方法执行独立复验。证据必须绑定当前方法 SHA、冻结评测合同、输入/seed、GPU 环境和结果；旧 SHA 的分数不能转移给净化或修复后的文件。
4. 最终候选失败时保留失败结果并回退到已经独立复验的稳定候选，不把失败候选的研究时间或分数改写为成功。

## 阶段二：拉回、核验并关机

1. 生成不自包含的远端逐文件清单：清单文件本身不得列入自己的哈希集合。排除系统缓存、临时锁、socket、解释器缓存和无权限伪文件；排除规则写入快照。
2. 把代码、轨迹、receipt、评测结果、最终方法、镜像/环境摘要与清单拉到机外持久位置。
3. 在本地逐文件核对路径集合、大小和 SHA256；归档 CRC 通过但逐文件清单失败时仍不得关机。
4. 核对没有仍需保留的 trainer、evaluator 或控制器进程，再执行操作系统关机；记录关机命令回执与 SSH 不可达检查。
5. 操作系统关机只证明主机不可达。云平台实例状态、自动释放和计费停止必须由 provider API 或控制台单独回读；无法回读时写 `OS_SHUTDOWN_VERIFIED / BILLING_STATE_UNVERIFIED`。

关机后才发现最终 SHA 未复验、哈希不全或清单自包含，通常意味着必须重新租用相同能力的实例。不要为了省几分钟费用把可恢复性留到关机后验证。

## 最终包重建

从核验后的白名单源重建新版本目录，不覆盖上一候选。测试使用外部 scratch 目录并设置不写字节码；打包前拒绝 `__pycache__`、`.pyc`、`.pytest_cache`、AppleDouble、编辑器缓存和测试临时目录。先生成成员清单，再生成确定性 ZIP，最后从 ZIP 本身独立复算成员集合与哈希。

旧候选若因缓存、旧哈希或声明漂移失败，保留为失败快照并明确判废；不得在原文件名上静默覆盖。
