# 完成提交与验收表

不同 tenant 可能把流程拆成多个页面、关联表或视图。不要依赖标签页顺序；按下面四个语义页面逐一映射到 live schema，并分别检查写权限。

## 需要提交的页面与字段

### 1. 身份映射页

- 当前期次、当期权威题号；
- 任务精确标题、论文 canonical ID；
- 领题记录关联；
- 提交人角色和提交批次。

题号只从当期领题表回读，不从 ZIP、目录名或旧 QA 报告复制。

### 2. 交付材料页

- 唯一主提交包或仓库 revision；
- 包/commit/release 的稳定标识和 SHA256；
- 任务说明、environment 与 tests 双 Dockerfile、Verifier/Hidden 证据；
- Baseline/Reference 原始结果与 comparison summary；
- 两条独立轨迹及逐轮字段；
- self-check/NOP、运行回执、恢复和资源证据；静态 QA 可把未运行 NOP 记为 `not_run`，但当期正式提交规则要求 NOP 时，必须提供同一产物版本的 NOP Trial 或可复核的平台既有记录，才能宣称提交 `READY`；
- QA 报告版本、结论和生成时间。

附件上传成功不等于字段已关联；上传后必须回读附件对象、摘要或关联记录。临时下载链接和本机路径不能作为稳定材料引用。

### 3. 提交人声明页

- 提交状态与提交时间；
- 适用的 QA 门禁及未验证边界；
- 已知风险、待补证项和下一责任角色；
- 隐私、许可证和再分发声明。

QA 存在硬失败时，状态只能保持待补证/未完成等当前 schema 允许的中性状态，不得写“已通过”。

### 4. 验收结论页

- 验收状态/结论；
- 结论说明和证据引用；
- 验收人、验收时间、适用 QA/协议版本；
- 返修项与复验条件（仅在确有缺陷且审核角色决定返修时）。

此页通常属于审核角色。先检查字段级权限；提交人能编辑材料页并不意味着可以编辑验收结论。

## 权限不可写时

权限是现场事实，不在公开 skill 中假定固定页面必然可写：

- **验收结论页只读：** 完成身份、材料和提交人声明页；生成逐字段验收草稿与证据索引，交给验收角色。保持结论未写，不代填通过或返修。
- **关联字段/公式字段只读：** 修改其权威源记录，或请表所有者修复关联；不直接覆盖派生值。
- **附件列不可写但文本列可写：** 仅在流程认可的受控存储上传，并填写稳定对象引用与哈希；没有认可替代存储则 `INCOMPLETE_PERMISSION`。
- **整表可读不可写：** 输出按 live schema 排列的待填草稿和私有证据包，由现任负责人代填并回传回读证据。
- **原 tenant 已不可访问：** 不从截图或旧导出伪造提交。由流程所有者指定新权威表并确认迁移范围；否则保持未提交。

替代路径不是降低验收标准。负责人代填后仍必须重新读取目标记录并核对题号、产物摘要和状态。

## 写入顺序

1. 锁定主提交包并计算摘要。
2. 独立 QA，区分静态通过、包内运行证据和未独立复跑项；当期规则要求 NOP 时，在冻结的同版本产物上完成或回读可复核的 NOP 记录。
3. 回读领题表取得当期题号。
4. 先写身份映射，再写材料和提交人声明。
5. 由有权限的审核角色写验收结论。
6. 回读四类页面，确认关联、附件、状态与时间一致。

顺序反了会使验收结论指向未冻结或错误题号的产物。新包替换旧包时，必须先更新材料及摘要、重新 QA，再更新结论；不能让旧结论短暂背书新附件。

## 完成标准

“已提交”要求前三类页面的必填字段和附件回读一致；“正式提交 READY”还要求当期规则指定的 NOP/平台运行门有同版本证据；“验收通过”则要求第四类页面由有权限角色写入，且所引用 QA 与当前主包摘要一致。任何受保护页面未写只能报告“材料已提交，验收待负责人回填”。
