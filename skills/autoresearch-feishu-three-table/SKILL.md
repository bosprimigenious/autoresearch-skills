# AutoResearch 飞书三表流转

把三张表视为有顺序的外部状态机，而不是三份可凭记忆填写的表单：当期领题表提供权威题号，完成提交/验收表绑定交付物，组长初检表记录复核结论。任何写入都只能使用当前已授权身份和当前期次的实时 schema；旧期导出、文件夹名、历史题号和聊天记录都不是权威源。

## 先识别当前动作

- 领取或登记论文：读 [三期领题表工作流](references/topic-claim-table.md)。
- 上传完成材料、申请验收或填写验收结论：读 [完成提交与验收表](references/submission-acceptance-table.md)。
- 对已登记项目回填组长初检：读 [组长初检表](references/lead-review-table.md)。
- 需要生成私有操作账本、判断可否宣称完成或处理跨表冲突：读 [共同状态与证据合同](references/state-and-evidence.md)。

## 共同执行顺序

1. **确认授权边界。** 只使用用户当前可访问的 tenant、文档和连接器。先做只读探测，记录资源类型、当前期次、表/视图、字段 schema、记录主键和读写能力。页面可见不等于表可写，能写记录不等于能改 schema 或验收字段。
2. **解析真实 schema。** 通过当前资源的元数据、字段列表和状态枚举匹配语义字段；不硬编码列序号、视图位置或旧字段名。无法列字段时停止，不通过猜测构造请求。
3. **建立跨表身份。** 以当前期次的权威题号为主键，同时核对规范论文标识、精确标题和交付摘要。只按项目展示名或模糊搜索命中不能写入。
4. **预演最小变更。** 写出目标记录、拟改字段、旧值摘要、新值摘要和证据引用。除用户明确要求外，不新增字段、改状态枚举、覆盖他人、删除记录或批量更新。
5. **按职责写入。** 领取人只填领取范围，提交人只填材料与自检，验收人或组长才填其受保护结论。用户要求提交材料不等于授权代替审核者判定。
6. **写后回读。** 重新读取目标记录，逐字段比较规范化值，并确认关联记录仍指向同一期次和题号。接口成功但回读不一致时记 `CONFLICT`，不得报告完成。
7. **保存私有操作账本。** 记录时间、资源逻辑名、记录主键的本地别名、字段变化、回执、证据哈希和未完成项。真实 URL、base/table token、record ID、用户 ID、姓名、邮箱和附件 capability URL 不得进入公开仓库、公开日志或 skill 示例。

## 权限失败

权限不足、账号失效、资源已转移或用户已经离开原组织时，不循环登录、不复用旧凭据、不请求扩大权限，也不尝试通过旧分享链接绕过访问控制。保留脱敏错误类别和请求阶段，结论写 `INCOMPLETE_PERMISSION`。替代路径只能是：由当前资源所有者授权新身份、由仍有权限的负责人代填经过复核的字段草稿，或迁移到用户当前控制且被流程认可的新表。

如果旧表不可访问，新表尚未被明确指定为权威源，则只能生成待填草稿和证据清单，不能宣称“已领取”“已提交”“验收通过”或“初检完成”。

## 完成条件

仅当目标记录唯一、题号来自当期权威表、字段与角色权限匹配、写入有成功回执且写后回读一致时，才能报告对应动作完成。三表是独立门禁：领题成功不证明提交成功，提交成功不证明验收通过，QA 通过也不自动等于组长已回填。
