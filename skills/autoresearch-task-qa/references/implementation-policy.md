# 默认实现情况判定表

本表是前置 G01–G03 之后的21项实现检查；内容门槛见 research-quality.md，三门结论独立参与总评。本表取代默认预检旧规则。判断“有没有实现相关内容”，不要求运行证明、完整对抗测试或独立复跑。接受等价结构和命名。纯 TODO、注释里说已实现、空函数、占位日志不算实现；不能机械用关键词或文件数量判通过。

| ID | 通过条件与检查方式 |
|---|---|
| QA01 | 读 instruction，八章节存在或有语义等价的八部分，未直接给出参考方法、论文标题、arXiv ID、repo 来源线索。通用背景知识与必要接口说明不是方法泄露。不强求标题逐字一致。 |
| QA02 | 读实际评分表达式与锚点配置，存在连续、按指标方向单调、未裁剪的归一化实现，hidden baseline 对应 0，预计上限对应 1。可静态代入或计算材料中的数字；不要求属性测试或 hidden 重跑。仅无关代码中的 clip 不构成失败。 |
| QA03 | 有参考实现、可识别运行入口，以及 `optimization_evidence/reference_runs/` 中正式 seed 对应的结果和非空日志；训练型任务还应有可追溯模型及重载记录。已有材料记录的归一化分数在 [0.15,0.8]。不要求本次执行或独立可信签名；发现明确超界、正式轮缺失或只有空声明则不通过。多交辅助文件不影响本项。 |
| QA04 | 确定性评估不适用；有波动则有 baseline/reference 同 seed 配对比较与 3σ 判定实现或计算记录。若提供原始正式 seed 数据，按 Baseline 原始指标样本标准差 σ_B（n−1）复算，maximize 为 R均值-B均值≥3σ，minimize 反向；核对均值、样本标准差、差值和判定，不只读取 `passed: true`。原始值足够时按当前规范复算；原始值缺失无法判定时记未完成；原始记录明确不满足则不通过。不要把固定训练 seed 自动等同 verifier 无波动。 |
| QA05 | 存在与题面核心约束对应的环境限制或 verifier 检查逻辑即可；不强求每条映射表/负向测试，但只有文字禁令没有执行逻辑不能通过。 |
| QA06 | 存在可识别的单命令入口、标量主分数计算和失败处理。结合 QA17 确认主分数写入 Harness 接收的 reward 文件；仅打印 score 或写自定义 result.json 不等于完成接口。允许 reward.json 中附加数值指标，不要求固定错误文案，不实际执行。 |
| QA07 | **只读 instruction.md**，未披露 hidden 样本/标签/可恢复答案的信息即可；提及 hidden 集合或禁止访问不算泄露。不审物理隔离。 |
| QA08 | **只读 instruction.md**，未披露参考解代码、具体配置/结果或直接答案提示即可；泛称“参考解”或禁令不算泄露。不审包内参考文件、镜像或历史。 |
| QA09 | 读 verifier 写结果调用链，存在预写结果清理以及原子替换逻辑即可；不额外要求 fsync、唯一临时名或完整竞态防护测试。 |
| QA10 | 有针对冻结面的可信副本恢复、只读权限或校验保护中的可识别实现即可；不要求独立 digest、最终镜像权限探针。目录名不是要求：没有 `trusted/` 不构成失败，仅目录叫 trusted 也不等于保护。 |
| QA11 | 逐一确认八部分有对应实质内容：目标输入输出、任务环境、指标公式、可改范围、禁止边界、提交格式、迭代流程、完成条件。接受同义表达、交叉引用，不检查固定句数或排版。 |
| QA12 | 没有 .git 可通过；有则查 remotes/tags/reflog 的清理结果或实际清理脚本及明显 fix/answer 线索，不强制深挖所有不可达对象。若只审核清理脚本，原因应写“存在清理实现”，不能写“已确认清理完成”。 |
| QA13 | `optimization_evidence/` 有 Baseline 与 Reference 全部正式 seed 的实际运行/原始指标记录，两者 seed 集一致并逐 seed 同向比较；Reference 汇总有提升且质量门通过。不要求本次复跑。归一化 baseline=0 是正常锚点，不是平凡分数；不得只凭随机输出、单独写 passed 或重复同一 checkpoint 冒充独立运行而通过。 |
| QA14 | 有可修改空间，并能从实现/分析中找到至少一种题面未直接提示的合法方法方向；参考分数未饱和。无需替专家研究或实证新解。面向用户/专家的私有报告可以介绍已交付Reference的方法；不得把这些报告或方法答案写回Agent题面。 |
| QA15 | **跳过，不检查。** |
| QA16 | **两条模型轨迹各自有效执行≥10h**；仅不涉及训练且单轮迭代很短的任务，两条各≥7h且具备例外资格证据、每条≥3有效方法闭环、后续方向、best_method干净重跑及真实有效时长证据时可接受。runtime_review由脚本核验，排队/安装/故障/阻塞不计，不相加；未知有效时长或例外资格记未完成；涉及训练/微调、迭代不短却不足10h，或任何轨迹不足7h，明确不通过。容器12h稳定性不等于此项。 |
| QA17 | **Harbor Harness 兼容性**：按 harbor-harness.md 完成 H01–H06，检查显式 separate、双 Dockerfile 的实际构建路径、公开 Dev 可用、私有 Hidden 材料及调用关系、独立依赖与 artifacts 移交。Hidden 目录名可灵活。必交一次当前题包版本的 NOP 自检记录，确认构建、Trial 和独立 Verifier 正常结束并产出有效 reward；缺少记录使 H06 与 QA17 fail。报告分开写静态接口结论与运行状态；0 分本身不判接入失败，可复用平台已有同版本记录。Oracle 不必交，不恢复 QA15 的资源门槛。 |
| QA18 | 两条与当前任务一致的独立 Agent 轨迹及方法演进分析，每轮八字段齐全，分数、失败原因和最佳标记可追溯；结果和有效时长与 run_summary/专家说明/实际记录交叉核对。缺一条须补齐，Reference 执行记录不能替代 Agent 迭代轨迹。轨迹属于另一题、与摘要矛盾或普通日志冒充 Harness 证据不能通过；声称 Harness 运行则交叉引用 H06。 |
| QA19 | 确定性 verifier 不适用；随机性评估在题面中只检查 seed 与有效提升阈值说明。**本 QA 项本身不要求题面额外说明重复评估规则、replicate 数或重复次数**，缺少这些文字不能判失败；但一旦正式协议已经声明多个 seed，`optimization_evidence/` 的提交完整性仍须按 QA03/04/13 与格式层核对全部已声明 seed，二者不要混淆。 |
| QA20 | 题面包含可改范围、网络规则和工具策略即可，允许“按平台默认工具策略”等有明确对象的引用，不要求固定 webSearch 大小写。 |
| QA21 | trajectory、expert_annotation、run_summary 可解析，核心内容与当前任务及 best method 相符。每轮八字段：round、policy_name、method_summary、status、score、failure_reason、retained_best、time；失败分数可 null，失败原因须真实。两条轨迹均在总览呈现；确实缺失不通过，无法访问则未完成。接受明确映射的等价文件名，不要求旧版额外 run_id、命令或资源字段。AutoResearch 轨迹与 Harbor ATIF 分开识别；声称 ATIF 才按对应版本检查。“Seed 2.1 Turbo High”是 Agent 模型名，不是训练随机种子。 |

## 证据复核

每项检查“文件存在 → 内容有效 → 对应要求 → 无明显反证”。引用待检文件的相对路径，可追加行号或 JSON 字段。日志是已有材料，不代表已独立确认真实性；报告原因如实写“已有记录”“存在实现”，不要写“本次复现成功”。格式层同时检查 `workspace/`、`expert_evidence/`、`optimization_evidence/` 的职责和轻量结构；超出推荐格式的项目分类为保留、可合并、放错位置或旧布局，单独写建议而不机械扣错。对阅读中发现的硬编码分数、造假日志、刻意削弱 baseline、使用 hidden 调参或评分入口接管等可疑情况记录具体证据，不推测动机、不扩大 QA07/08 检查面。

## 总结论

- G01–G03与所有适用QA项通过且复核完成：通过。
- 任何内容门或适用QA项有明确失败：不通过，同时保留复核是否完成。
- 无已证实失败，但有无法读取/无法判断项或未完成语义复核：未完成检查。
- QA15 始终跳过；QA04/QA19 的不适用必须说明评估确定性的依据。
